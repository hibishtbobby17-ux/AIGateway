Internal Mechanics

Component Diagram & Request Flow

Detailed look inside the Go Data Plane engine and Telemetry Ingestion pipelines.

Data Plane Proxy Engine Inbound Pipeline
1
TLS Termination & Concurrency Guard

Enforces max in-flight concurrency with load shedding (HTTP 503 + Retry-After). Configurable TLS 1.3 cipher suites.

2
Token-Bucket Rate Limiter & Auth

Verifies OAuth 2.1 PKCE bearer tokens against in-memory JWKS cache and checks durable Redis token revocation.

3
Guardrails & Schema Virtualizer

Masks sensitive credentials/PII, blocks prompt injection, and dynamically virtualizes MCP tool namespaces ({prefix}__{name}).

4
SafeDialer Egress & Bulkhead

Per-host semaphore isolation preventing thread starvation. Drops requests to RFC 1918 private IPs and AWS/GCP metadata services (169.254.169.254).

5
Circuit Breaker & Failover

Tracks 5xx error rates and p99 latency spikes. Automatically fails over from Azure to AWS Bedrock in <15ms.

Ingest Service Engine Telemetry & Audit Pipeline
1
In-Memory Channel Buffer

Gateway batches spans into a high-speed Go channel (5,000 capacity) with periodic 400ms ticker flushes to Ingest API.

2
Fail-Safe Disk Spooler Spillover

If network fails or channel saturates, logs immediately write to append-only JSONL file (`gateway_events.spool`).

3
Redis Streams Queue (`ai_gateway:events`)

Ingest service buffers events into partitioned Redis Streams with consumer groups for horizontal autoscaling.

4
Idempotent Dual-Write Workers

Drains stream into PostgreSQL (`ON CONFLICT (event_id) DO NOTHING`) and HTTP-batched ClickHouse columnar tables.

5
Cold Storage Parquet Flusher

Compiles 60-second micro-batches to compressed Apache Parquet in AWS S3 for zero-compute Athena queries.

High Availability & Edge Cases

Fault-Tolerance & Failure Modes

How AIGateway guarantees zero data loss and prevents socket/goroutine leaks during real-world network turbulence.

Scenario 1: Upstream Connection Drops Mid-SSE Response
SSE Stream Lifecycle

Long-lived Server-Sent Events (SSE) between clients (Cursor, Claude Desktop, autonomous agents) and upstream LLM providers (OpenAI, Bedrock, Anthropic) are prone to mid-response socket drops. Here is how AIGateway manages cleanup, partial chunks, and re-connection:

Phase 1 Context Bind
Go Context Propagation

Every stream ties directly to client `r.Context()`. Downstream HTTP dialers and Bulkheads listen for parent cancellation signals.

Phase 2 Drop Detected
Socket Interruption / EOF

When upstream TCP drops or resets, `io.Read` immediately returns `io.ErrUnexpectedEOF` or connection reset without hanging.

Phase 3 Partial Flush
Clean Error Frame

Emits an explicit SSE error event (`event: error\ndata: {"error":"upstream_reset"}`) so the consumer client knows the stream was truncated.

Phase 4 Leak-Free Cleanup
Semaphore Release

Defers unlock the per-host Bulkhead channel, closes sockets cleanly, and emits partial byte/token telemetry with error tags.

// Client Reconnection Guarantee:
Clients can resume stateful agent tasks using the standard Last-Event-ID header. The gateway correlates task state machines and avoids re-executing non-idempotent tool calls.
Scenario 2: Full Telemetry Buffer & Backend Outage (ClickHouse Down)
4-Tier Fail-Safe

When downstream analytics sinks (ClickHouse, OpenSearch) undergo maintenance or fail, the gateway must never drop logs or block the active LLM request data plane. We enforce a 4-tier spillover architecture:

Tier 1 Memory Ring
Go Channel Buffer

Fast non-blocking `select` on buffered channel (5,000 events capacity). Ticker flushes batches every 400ms.

Tier 2 Spillover Disk
Local Append-Only Spool

When queue fills or Ingest returns non-200, events immediately write as JSONL to `gateway_events.spool` (capped at 20MB).

Tier 3 Durable Stream
Redis Streams Queue

Ingest service places received events in durable `ai_gateway:events` streams, decoupling database writes from network requests.

Tier 4 Self-Healing
Autonomous Replay

A background `diskDrainerLoop` probes health with backoff, replays spooled disk events, and PostgreSQL retains duplicate-proof records.

// Zero-Loss Guarantee:
PostgreSQL inserts use ON CONFLICT (event_id) DO NOTHING. Even if ClickHouse is offline for hours, traces remain intact in Postgres and Redis, backfilling automatically when ClickHouse reconnects.

Developer Experience

Zero Code Changes Required

Works seamlessly with existing SDKs by updating just the base URL.

import os
from openai import OpenAI

# Direct standard OpenAI SDK to your secure AI Gateway instance
client = OpenAI(
    base_url="http://localhost:8080/api/llm/production-models/v1",
    api_key=os.environ.get("GATEWAY_API_KEY", "ak_live_enterprise_secret")
)

# Gateway handles token metering, PII masking, and routes to Azure or Bedrock
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "You are a secure corporate assistant."},
        {"role": "user", "content": "Analyze our infrastructure quarterly billing metrics."}
    ],
    temperature=0.2
)

print(response.choices[0].message.content)
import OpenAI from 'openai';

const openai = new OpenAI({
  baseURL: 'http://localhost:8080/api/llm/production-models/v1',
  apiKey: process.env.GATEWAY_API_KEY || 'ak_live_enterprise_secret',
});

async function main() {
  const completion = await openai.chat.completions.create({
    model: 'claude-3-5-sonnet', // Transparently transformed and routed to Bedrock or Anthropic
    messages: [{ role: 'user', content: 'Generate security audit checklist' }],
  });
  console.log(completion.choices[0].message.content);
}

main();
